# @kkutysllb/dsh-terminal 1.3.0

## 变更

- **新增：标签前置终端图标**
  - 每个标签在目录短名前加一枚终端图标（提示符母题，与标题栏开关按钮同一套
    笔画）。图标随状态变淡：非活动 `.48`、活动 `.9`、已退出 `.28`。

- **新增：header 展示当前 shell 名**
  - header 右侧新增 shell 徽标（等宽字体胶囊），显示**当前活动标签真实使用的
    shell 短名**：`zsh`（macOS 默认）、`bash`（Linux 默认 / 兜底）、`pwsh` /
    `powershell`（Windows 探测链落点）。
  - **取值来自服务端，不是客户端按平台猜的**：`entry.js` 的
    `tabOf(s).title = shellDisplayName(s.shell ?? defaultShell())`。也就是说
    徽标反映的是 `$SHELL` → passwd 登录 shell → bash 兜底这条链的**实际
    落点**，以及 `DSH_TERMINAL_SHELL` 覆写后的结果。按平台硬编码（darwin →
    zsh）会在用户自定义 `$SHELL` 时显示错误信息，也会在 spawn 回退到 bash
    时与真实进程不符。
  - 徽标跟随活动标签切换；无活动标签（桶空 / 全部关闭）时整体收起，不留空
    胶囊，也不残留上一个标签的 shell 名。

- **修复：面板镀铬「边框痕迹粗糙」**
  - **根因**：上缘拖条是 4px 的**实心填色**（`panel.grip.style.background =
    token.border`），亮色主题下就是面板顶部一条突兀的灰杠；同时面板没有上
    边框、圆角与投影，读起来是个生硬的矩形。
  - **改法**：拖条命中区保留并加大到 6px，但改为**常态隐形、悬停浮出一枚居中
    胶囊、按下染强调色**（停靠区手感）；面板加 1px 上分隔线 + 10px 上圆角 +
    向上投影。
  - 分隔线与徽标底色**不再硬编码** `rgba(0,0,0,.10)`（该值在暗色主题下会脏成
    灰线），改为 `color-mix(in srgb, <fg> N%, transparent)` 从既有 token 现
    算，亮暗自动跟随且色相与正文一致。
  - 随改动删除 `themeOf()` 里已成死代码的 `border` token —— 留一个没人读的
    硬编码色值就是给回归留口子。

- **修复（顺带）：依赖降级卡在暗色主题下是一块白板**
  - `ensureDepsPanel()` 此前从不调用 `applyPalette()`，面板底色落回 CSS 里
    的 `background:#fff`；`body[data-ds-dark-theme]` 翻转时的重涂也遍历不到
    它（它已在 `panels` 里，但自身没有 palette）。现构建即调 `applyPalette`。

## 升级

```bash
dsh plugin --profile <name> add @kkutysllb/dsh-terminal@latest
```

官方桌面端 UI 无原地更新时：插件详情页「卸载」→ 安装框重装
`@kkutysllb/dsh-terminal`。纯 client 面改动，**刷新页面即生效**（无需重启引擎）。

## 验证

三层，全部真跑：

| 层 | 命令 | 结果 |
|---|---|---|
| 契约形态（静态） | `node scripts/smoke-plugin.mjs` | **30/30**（新增 9 条） |
| 服务端纯函数 | `node tests/run-tests.mjs` | **14 passed**（未触碰 entry.js 半） |
| **真 DOM 端到端** | Electron + 真 Chromium + 桩 API，加载**原样** `client.js`（不入仓的 `staging/probe-terminal-client.mjs`）：驱动真交互后断真 DOM 与 computed style | **25/25** |
| 负对照（DOM 层） | 同一探针指向 `git show HEAD:client.js`（v1.2.2） | **10/25**，15 红全是新能力断言 |
| 负对照（静态层） | 旧 `client.js` 副本跑冒烟 | **21/30**，9 红 = 新增 9 条 |

真 DOM 层里最值钱的一条：桩里**新建**标签的 `title` 是 `bash`（活动标签是
`zsh`）——点「+」后徽标变成 `bash`、关掉又回到 `zsh`。这证明徽标取自服务端数据
并在活动标签切换时刷新，**不是客户端按平台猜的常量**。服务端那条解析链
（`$SHELL` → passwd → bash 兜底；Windows 的 `DSH_TERMINAL_SHELL` 覆写与 pwsh
探测链）由 `tests/run-tests.mjs` 既有用例覆盖，本轮补上的是「服务端值 → header
徽标」这一段。

负对照顺带把「边框痕迹粗糙」量成了数字：

| 量 | v1.2.2 | v1.3.0 |
|---|---|---|
| 拖条本体 `backgroundColor` | `rgba(0,0,0,0.1)` ← 亮色下那条灰杠 | `rgba(0,0,0,0)` |
| 拖条命中区高 | `4px` | `6px` |
| 面板上边框宽 | `0px` | `1px` |
| 面板上圆角 | `0px` | `10px` |
| 面板投影 | `none` | 非 `none` |
| 分隔线取值 | 硬编码 `token.border` | `color-mix(in srgb, <fg> 14%, transparent)` |
