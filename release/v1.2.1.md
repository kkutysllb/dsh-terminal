# @kkutysllb/dsh-terminal 1.2.1

## 变更

- **修复 KCoder 桌面端按钮落位回归（v1.2.0 引入）**：
  - **锚点竞态**：v1.2.0 的锚点链按「注入时谁在用谁」，而 KCoder 壳的标题栏由主进程 `executeJavaScript` 在 did-finish-load 注入，时序可能晚于 React 会话头首帧——竞态窗口内按钮先落 corner 回退位，且「按钮已存在即 present」的巡逻短路让它**永不迁回**标题栏（v1.1.x 只认标题栏、会一直等，反而无此问题）。现巡逻加**锚点升级**：corner 仅为回退位，标题栏一旦出现即迁回 v1.1.x 位形（`right:44` 绝对定位、26px），原生壳无标题栏 → 永驻 corner 不受影响。
  - **样式表选择器笔误**：v1.2.0 引入 `:not(.kt-corner)` 隔离时首条规则丢了 `#` 前缀（`__dsh_kc_term_btn:not(...)` 成了永不匹配的类型选择器），标题栏位形按钮完全裸奔（UA 默认样式、文档流内联）。已补回。
  - **孤儿按钮旧洞（顺带）**：锚点宿主被上游整表重写后脱挂的按钮占住 id、巡逻永远 `present` 不重建（v1.1.x 起即存在）——现在脱挂视为缺失，原地重建。
- 隔离复现实测：标题栏晚到 3.5s 场景下，按钮 corner 落位 → 巡逻迁回标题栏（`position:absolute; right:44px; width:26px`）；原生壳（无标题栏）场景 corner 永驻 + 点击开合正常；KCoder 路径回归 v1.1.x 观感。

## 升级

```bash
dsh plugin --profile <name> add @kkutysllb/dsh-terminal@latest
```

官方桌面端 UI 无原地更新时：插件详情页「卸载」→ 安装框重装 `@kkutysllb/dsh-terminal`。
