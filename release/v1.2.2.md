# @kkutysllb/dsh-terminal 1.2.2

## 变更

- **修复：dsh `0.2.1-alpha.1` 下整个 bundle 被静默跳过（兼容门上界过窄）**
  - **现象**：升级到上游 `dsh-v0.2.1-alpha.1`（2026-10-03 prerelease）后，内置终端
    **整块消失**——无报错、不崩溃；app-boot 兼容闸门只在 stderr 留一行
    `skipping profile bundle`（`packages/boot/app-boot/src/profile.ts`）。
  - **根因**：`peerDependencies` 上界 `>=0.1.6-alpha.2 <0.2.0` 对运行时
    `0.2.1-alpha.1` 求值为 **false**。旧范围只在 `0.2.0-rc.*` 世代侥幸成立
    （semver 里 `0.2.0-rc.2 < 0.2.0`），上游一旦跨过 `0.2.0` 边界即失配。
    检查器实现见 `packages/boot/app-boot/src/plugin-compatibility.ts`
    （`semver.satisfies(runtimeVersion, range, { includePrerelease: true })`）。
  - **修复**：上界改为 **`<1.0.0`**，覆盖 `0.1.x` 与 `0.2.x` 全系（含 prerelease）。
    `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-host-webserver` 两条 peer、
    以及 `engines.dsh`（声明性文档，与 peer 同口径）一并更新。
  - 该范围**放宽**是向后兼容的：旧范围覆盖的 0.1.6-alpha.2 → 0.2.0-rc.2 仍在新范围内。

## 升级

```bash
dsh plugin --profile <name> add @kkutysllb/dsh-terminal@latest
```

官方桌面端 UI 无原地更新时：插件详情页「卸载」→ 安装框重装 `@kkutysllb/dsh-terminal`。

## 验证

- `node scripts/smoke-plugin.mjs` **21/21 通过**（含 `engines.dsh == 兼容范围` 与两条 peer 断言）。
- 语义实测（semver 7.8.5，`includePrerelease: true`）：

  | 运行时 | `>=0.1.6-alpha.2 <0.2.0`（旧） | `>=0.1.6-alpha.2 <1.0.0`（新） |
  |---|---|---|
  | `0.2.0-rc.2` | true | true |
  | `0.2.1-alpha.1` | **false** ← 旧范围在此被 deny | **true** |
